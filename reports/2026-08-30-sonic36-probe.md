# SONIC 3.6 PROBE — 2026-08-30

**Verdict: `sonic-3.6` does not exist on Retell.** The API rejects it with HTTP 400 and returns
the entire legal `voice_model` enum in the error body. `sonic-3-latest` is the newest string
Retell will accept.

**PR #52 is HELD, not merged.** Its script did not execute clean end-to-end.

## 3. Why PR #52 is held

The script executed steps 1 and 2 correctly, then died at step 3:

```
=== 3. CLONE — CREATING ===

FAILED GET /get-retell-llm/undefined -> HTTP 404
{"status":"error","message":"Not Found"}
EXIT_CODE=1
```

**Cause.** The clone path hard-assumes `response_engine.type === 'retell-llm'` and reads
`src.body.response_engine.llm_id`. `AI CHAUFFEUR FLOW v1` is a **conversation-flow** agent, so
that field does not exist, `srcLlmId` came back `undefined`, and the script requested
`/get-retell-llm/undefined`.

It failed **before** any create call, so the dead run left zero objects behind and mutated
nothing.

**The trap worth keeping.** The write-guard is populated from a field on the source object:

```js
const srcLlmId = src.body?.response_engine?.llm_id;
if (srcLlmId) LIVE_READONLY.add(srcLlmId);
```

Because the field was absent, the guard silently added nothing and printed
`llm_id : (none) — added to write-guard` — a line that reads like a success. A probe that builds
its own safety list out of the source object inherits that object's engine type as an unstated
precondition, and announces the gap as if it were a result.

**Second defect, latent.** The ladder loop `break`s on the first acceptance. Since
`sonic-3-latest` is accepted, `sonic-3.5` would never have been tested — the run would have
reported an acceptance matrix with the control row missing, and no error.

path and is held; landing a second probe script would fork the tool.

## 6. Gotchas

- **`sonic-3.6` is not a Retell string.** Do not put it in a payload; it 400s the whole request.
- **An invalid enum value returns the whole legal enum.** One deliberate 400 is the cheapest way
  to get Retell's real list. Same trick as the earlier voice-id enum probe.
- **`get-agent` returns the DRAFT.** The probe is `v0 published=false`; that is what the
  dashboard ear test plays, which is what we want here.
- **The live chauffeur rail was not changed.** It is still `v21 / sonic-3.5 / cartesia-Kate`.
  Moving it to `sonic-3-latest` is a decision, not a cleanup, and it has not been made.
