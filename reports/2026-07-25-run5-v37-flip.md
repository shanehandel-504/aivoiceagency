### ⚠ DEFECT FOUND — wrong phone number written to CRM

`book_appointment` was invoked with:

    "cell": "+14142408930"

That is **AVA's own published line**, not the caller's number. §14 PHONE NUMBER LAW says never to
ask for the number *because the call already provides it* — but the value handed to the tool was
the company's own number. **The GHL contact created by this booking carries AVA's number as the
lead's cell.** The prompt cannot fix this on its own; whatever populates `cell` needs to read the
caller ID. **This defect is now live on main**, since main runs the same prompt and the same tool.

### Note on B (begin_message)

The instruction stated the test agent "opened with a generic *how can I help you*" because
`begin_message` was empty. The recorded transcript shows the opening was in fact the correct
scripted §4 line — the model produced it from the prompt. Setting `begin_message` is still the
right call: it makes that first line **deterministic** rather than model-produced. Recorded here
only so the reason on file matches what the tape shows.

### The 10-minute cap was load-bearing

The call ran **233.6s**. Under the previous **180s** cap it would have been cut off roughly a
minute *before* the booking fired — mid-way through discovery. Carrying the 10-minute cap to main
is what lets a full CONFIRM-THEN-FIRE sequence complete.
