## GOTCHAS

**1 · P0 for the test agent — the booking tool contradicts the new prompt.**
`book_appointment` declares `required: ["name","email","cell","slot"]` and the LLM runs
with `tool_call_strict_mode: true`. The new prompt adds **PHONE NUMBER LAW — Never ask the
caller to speak their phone number.** So on a web test — where there is no inbound
`from_number` to fill `cell` from — AVA can only stall at the booking or invent a number to
satisfy the schema. Inbound phone calls are less exposed because call metadata can supply
it. This was out of scope for this run (prompt + KB + settings), so **nothing was changed**.
The fix is one of: drop `cell` from `required`, or let the prompt fill it from call
metadata. Needs your call.

**2 · A completed web-test booking creates a REAL GHL appointment.**
`book_appointment` still POSTs to the live n8n webhook
`https://circulant.app.n8n.cloud/webhook/ava-book-appointment`. Carried forward from the
build run and still true. Test the conversation, not the booking, unless you want the row.

**3 · Two different agents are named "AVA SALES v37 TEST".**
`agent_44b48507d38c0bfc29a3150a74` (this run's target, now v2) and
`agent_1fdc1e908e9a4fae46631adab5` (v2, published, 13,141-char prompt, no KB). Selecting by

**4 · The ordered prompt says "demo with the team"; MESSAGE FORMAT LAW says otherwise.**

"not demo"** — and the GHL calendar is configured to match. The final prompt says "a booked
demo with the team" / "a short demo with the team" in four places. Per § 0 PRECEDENCE a
direct instruction outranks the file, so it was written **byte-exact as ordered** and not
silently reworded. Flagging because copy and booking system now disagree.

**5 · Retell version semantics — the trap that cost four attempts.**
- `PATCH /update-agent` on a published version → **422** "Cannot update published agent"
- `PATCH /update-retell-llm` on a published one → **400** "Cannot update published LLM"
- No LLM-version-create endpoint exists (`/create-retell-llm-version`, `/create-llm-version` both 404)
- `response_engine.version` **must equal** the agent version → 400 otherwise
- `POST /create-agent-version` takes `base_version` **only**; any extra key → 400 "must NOT have additional properties"

The working sequence: **fork with `create-agent-version`, which mints the agent AND its
paired LLM at the same new unpublished version**, patch both drafts, then publish. A first
attempt created a separate new LLM to carry the prompt — that route dead-ends on the
version-coupling rule. That orphan (`llm_87d275e7d1a731cbf1c9f484beb3`) was deleted, 204,
after confirming zero agents referenced it.

**6 · `knowledge_base_texts` must be a JSON-encoded ARRAY.** A bare `{title,text}` object
400s with `"not an array"`. The endpoint is `multipart/form-data`, not JSON.

the underlying provider id, and **two** custom voices in the account carry the identical
name "Ava – Eager, Helpful and Understanding"
