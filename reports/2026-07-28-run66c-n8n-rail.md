## FIX 1 · LIVE INTAKE v1 / `Grok Extract` — **NO REPAIR NEEDED**

**The brief asked for a repair. The honest answer is that there was nothing left to repair,
and the reason is worth more than the fix.**

### Root cause, recorded

The `jsonBody` expression used to inline an HTML-stripping regex chain:

```
content: String($json.data || '').replace(/<script[\s\S]*?<\/script>/gi,' ')…
```

Written **inline in an n8n expression**, `[\s\S]` and `<\/script>` come back from the API
round-trip **double-escaped**. The expression then no longer parses, and n8n throws
`ExpressionError: invalid syntax` — with no hint that escaping is the cause.

### It was already fixed, and the evidence is in the execution log

| Execution | Time | `Grok Extract` |
|---|---|---|
| 4330 | 2026-07-23 **02:58:22** | **ERROR — "invalid syntax"** |
| 4331 | 2026-07-23 **02:59:43** | **OK** ← 81 seconds later |
| 4344 | 2026-07-23 03:05:04 | **OK** |

The repair was to move the regexes out into the `Strip HTML` **Code** node — where a single
backslash stays a single backslash — and have `Grok Extract` read `$json.page_text`. That
node carries its own comment explaining exactly this.

### Why two reports called it open

Both RUN 6.5's "STILL OPEN" list and `reports/2026-07-26-ops-map.md` recorded **"4 real
failures."** That was a stale **14-day failure count**, not a live check. Of those 4, **3
were the quota outage** (`Execution limit reached`) and only **1** was `Grok Extract` — the
one already fixed. Nobody re-ran it.

### What was done instead

- **Verified the live shape**: no backslash anywhere in the expression, reads
  `$json.page_text`, `Strip HTML` is a Code node. **PASS.**
- **Verified the repo cannot regress it**: `tools/n8n_live_intake.py` (the builder that owns
  this workflow) already emits the fixed shape, so a redeploy is safe.
- **Swept every active workflow** for the same double-escape trap in inline expressions —
  **clean, zero hits.**
- `tools/n8n-rail-repair.mjs` now **asserts** the repaired shape on every run, so this can
  never silently come back.

> **A note on method.** The first lint I wrote reported 3 more traps in the SMS nodes. All 3
> were false positives — the lint was written through a bash heredoc, which mangled its own
> regex from two backslashes to one. Measuring the actual character codes showed the SMS
> bodies hold a single `\n`, which is correct. This is the heredoc trap already in the repo's
> memory, and it bit the tool built to find it.

## FIX 3 · "Booked: unknown" — **FIXED**

### Root cause

```js
const booked = (cad.booked === true || cad.booked_appointment === true) ? 'yes' : 'unknown';
```

`custom_analysis_data` carries **only** `caller_first`, `caller_email`, `caller_phone`,
`business_name`. **There is no `booked` key and there never was.** So the test was always
false and the summary always said `unknown` — on booked and unbooked calls alike. Measured
on the real 2026-07-26 booked call:

```
custom_analysis_data: {"caller_first":"Chris","caller_email":"…","caller_phone":"…","business_name":"plumber service"}
Booked: unknown          ← while the call had genuinely booked appointment zWAdbE9q4SQ62OUGWcjL
```

### The real appointment result

It was in the payload the whole time — the `book_appointment` tool call, paired to its
result by `tool_call_id`:

```json
{"role":"tool_call_invocation","tool_call_id":"call_QYH…","name":"book_appointment"}
{"role":"tool_call_result",    "tool_call_id":"call_QYH…","content":"{\"success\":true,\"appointment_id\":\"zWAdbE9q4SQ62OUGWcjL\"…}"}
```

### The new branch table

| Situation | Reads |
|---|---|
| Tool call succeeded | **`yes`** + the real appointment id and time |
| Tool never invoked | **`no`** · *no booking attempted* |
| Tool returned `success:false` | **`no`** · the tool's own reason (e.g. `slot_unavailable`) |
| Tool invoked, no result recorded | **`unknown`** · *the one case we genuinely do not know* |

**It deliberately does NOT trust `call.tool_calls[].success`** — that flag is
transport-level, so a `slot_unavailable` refusal would still read `true` and produce a false
`yes`. It is used only to detect an *attempt* when the transcript is missing.

The **owner SMS** now carries `BOOKED` / `BOOKING UNCONFIRMED`, and the **owner email**
inherits the fix automatically (it renders `Format Call Log`'s `log_body`).

## GOTCHAS WORTH KEEPING

1. **A whitelisted n8n `PUT` that omits `settings.errorWorkflow` silently DETACHES the Error
   Sentry** — the exact silent-nothing failure the sentry exists to catch. The tool now
   carries the key forward explicitly. Verified all 13 still attached.
2. **A stale failure COUNT is not a live defect.** Two reports carried "4 real failures"
   forward for five days; 3 were the quota outage and the 4th was fixed 81 seconds after it
   happened. Re-run before you re-report.
3. **Clearing a Retell draft does not change what answers the phone.** A number bound with
   no `agent_version` serves `latest_published`. Check the published version, not the draft.
4. **`call.tool_calls[].success` is transport-level, not business-level.** Trusting it would
   report a booking on a `slot_unavailable` refusal.
5. **`custom_analysis_data` is not a contract.** It carries whatever the analysis prompt
   defines and nothing else — never assume a key exists because the code reads it.
6. **A lint written through a bash heredoc can mangle its own regex** and invent false
   positives. Write the script to a file; measure character codes, not appearances.
7. **Retell `webhook_url` is versioned**, so on an auto-publishing account it cannot be
   changed without moving `latest_published`.
