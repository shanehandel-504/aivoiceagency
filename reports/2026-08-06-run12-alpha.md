## 1 · THE RUN COULD NOT SHIP THE BRIEF AS WRITTEN, AND THIS IS WHY

§ 0b asked for a sweep of four over-claiming phrases. **All four read zero.**
The problem was in the other direction, and it was sitewide.

RUN 12's approved status vocabulary says direct write-back is *available on a
supported platform after setup verification*. Six shipped pages and `llms.txt`
said the opposite, **absolutely**:

| Where | What it said |
|---|---|
| `llms.txt` × 3 | "does not write into anyone's dispatch software" · "writes into none of them" · "does not write reservations into an operator's dispatch software" |
| `/works-with-your-software/` × 6 | "has no account in any of them" · "no way to change a record there" · "AVA never signs in to Limo Anywhere" |
| `/how-setup-works/` × 2, `/after-hours-limo-dispatch/`, `/limo-answering-service/` | "AVA does not write into your dispatch software" |
| `index.html` | the same denial, in a schema comment and in a FAQ answer |

§ 4 of the brief also says the automation page must **not contradict the live
FAQ**. That instruction and the § 1 table cannot both be satisfied while those
sentences stand. Shipping the new pages on top of them would have left the site
answering the same question two different ways — worse for a reader than either
answer alone, and much worse for an answer engine, which has no way to prefer one.

**23 sentences were reconciled.** Every absolute denial became a bounded one
against the same condition, and the condition is always the same: *configured and
tested against your account, then verified.* Visible copy only; the FAQPage
JSON-LD was regenerated from it by `aic-run10-faq-mirror.py` rather than
hand-edited, because editing both by hand is what put them out of step originally.

**The default did not move.** Shared-inbox delivery is still included in every
setup, a person still enters the trip on most setups, and a person confirms every
trip on every rung. What changed is that the site now states the condition under
which that default changes instead of denying that it ever does.

This is recorded as **THE CLAIM LADDER** in `DESIGN-SYSTEM.md` § 3.6 so the next
run does not have to re-derive it.

## 2 · THE TABLE, AND THE COLOUR IT DOES NOT HAVE

Eleven rows, **two columns**, five status strings and no sixth. Seven rows read
`Custom integration review` because seven platforms are at custom integration
review; the repetition is the signal, not an oversight.

Two columns rather than three is the literal reading of *"EXACTLY this vocabulary
and nothing else"* — a third column would have needed content that differentiates
platforms which are genuinely at the same stage, and inventing that difference is
the failure the sweep exists to prevent.

**The column is deliberately unpainted.** Every value names a *stage of setup*,
not a state that is true on screen. STATE LAW gives `--success-green` to an action
that has actually succeeded, beside a label naming it. A three-tier colour ladder
down eleven rows would have made eleven live-connection claims in one glance —
and it would have looked like evidence. `--ink-soft` throughout, 9.78:1 on
`--surface`, saying exactly what the words say.

**"Production verified" appears nowhere on the host.** The gate asserts its
absence on all sixteen pages. `writeback-flip.md` still owns that day.

## 3 · FOUR TRAPS, THREE OF THEM SILENT

### 3.1 · Three tools were globbing one level down

`stamp_chauffeur.py`, `aic-run10-faq-mirror.py` and `aic-run10-greps.py` all
matched `*/index.html` only. `/integrations/limo-anywhere/` and
`/integrations/fasttrak/` are the first pages on this host at depth **two**.

All three would have walked straight past them. No error, no warning:

- the two pages would have shipped referencing `/assets/aic.css` with **no
  version token at all** — the exact stale-cache failure the stamp tool exists
  to prevent — and `--check` would have reported every page current;
- the FAQ mirror would have printed *"every FAQPage node mirrors its visible
  copy"* about a set that did not include either of them;
- the grep gate would have printed **ALL CLEAN** about two files it never opened.

Fixed in all three, and the fix was verified by enumerating the scan set rather
than by trusting the print-out.

### 3.2 · The hub's status column was off-screen at 390

`.tbl` carries `min-width:620px` inside a `.tbl-wrap{overflow-x:auto}` — a
reasonable floor for a three-column table and plainly wrong for two. Photographed
at 390 before the fix, the entire status column was to the right of the viewport
and all a reader saw was a list of platform names.

`min-width:0` alone was not enough, and the measurement said why:

```
.tbl th is white-space:nowrap in BOTH the head and the row header
columns measured 242 + 182 = 424 inside a 340px box
242px was the platform column holding "Santa Cruz (GroundWidgets)" on one line
```

Letting the row header wrap **on a phone only** closes it. A two-line platform
name is not a defect; an invisible status column is.

### 3.3 · A scrollable table nobody could scroll

The three-column tables still scroll, and two things were missing — both defects
rather than polish. `overflow-x:auto` creates a **scrollable region**, and a
region that is not focusable cannot be scrolled without a pointer. And nothing on
screen said there was anything to the right, so the clipped column read as broken.

`tabindex="0"` + `role="region"` + `aria-label`, and a `.tbl-hint` that renders
below 668px — the width at which a 620px table stops fitting `.wrap`'s content
box. **This also repaired `/works-with-your-software/`**, which has scrolled
silently on every phone since RUN 10 and which this run's probe found while it was
checking the new pages.

The `display:block` stacked-card trick was rejected: it drops the table role out
of the accessibility tree in every major engine, and a status table whose rows no
longer associate with their column heading is a worse outcome than the scroll.

### 3.4 · `details > div a`, the three-CSS-homes trap again

Declared in `assets/aic.css` and nowhere else. On the eleven pages that load it,
a link inside an FAQ answer is blue **and underlined**; on the homepage — which
carries its own embedded copy of the shell — the base `a{text-decoration:none}`
won and **colour was the only thing marking the link**. The homepage FAQ has
carried one since the section shipped.

RUN 9 fixed exactly this for `.sec-sub`, `.card-p`, `.vs-b` and the rest, and
listed the selectors it covered. `details` was not among them and nothing since
had looked. Lighthouse reads 100 there either way — **the audit is not the rule.**

Redeclared in the RUN 12 block, which is byte-identical in both homes by law, so
it cannot land on one head and miss the other.

## 4 · THE DEFECT THE GATE FOUND IN THE RUN'S OWN WORK

All four pages shipped with `.page-sub` sitting between the H1 and the direct
answer. The first prose an answer engine met was therefore a *shorter summary of
the answer directly underneath it* — a redundancy for a reader and an ambiguity
for anything trying to lift one paragraph off the page.

`aic-run12-gate.mjs` probe 2 asserts the answer is the first prose in `<main>`,
and it failed on 4 of 4. **The pages were fixed, not the probe.** `.answer` is
17px prose in the deck's slot and already does the deck's job, so the deck came
out; the one line worth keeping moved down into the section whose argument it
opens.

## 8 · GOTCHAS FOR THE NEXT RUN

1. **A glob is a silent gate.** Three tools walked one level and would have
   reported clean about two files they never opened. Enumerate the scan set;
   never trust the summary line.
2. **A shared CSS block is prose and rules together, and CSS raises no parse
   error.** A stray `*/` mid-comment left the following rule swallowed as part of
   a malformed selector — `.tbl--pair` silently stopped applying. Check comment
   balance before writing, and let a render probe be the backstop.
3. **`white-space:nowrap` on a row header sets a table's minimum width.**
   `min-width:0` does not override it. Measure the columns.
4. **`overflow-x:auto` creates a keyboard trap in reverse** — a region nobody
   without a pointer can reach. `tabindex` + a role + a visible hint, or don't
   scroll.
5. **Git Bash rewrites a bare `/path/` argument** into
   `C:/Program Files/Git/path/`. The only symptom is
   `CHROME_INTERSTITIAL_ERROR` on every run, which reads like a network fault.
   `MSYS_NO_PATHCONV=1`, and have the tool refuse the malformed argument.
6. **A Lighthouse report can exist and still be unusable.** Reading
   `.numericValue` straight off an audit throws inside the loop and turns one bad
   report into a dead sweep.
7. **One Lighthouse run is noise in both directions.** A single 99 is not a
   finding and a single 100 is not a pass.
8. **RUN 11's anchor sweep only covers the homepage's anchors** plus the skip
   link on every other page. Anchors added on a NEW page are swept by
   `aic-run12-gate.mjs` probe 13. If a future run adds pages, extend one of the
   two — neither does it automatically.
9. **`/book/` reports Best-Practices 79**, from its third-party booking iframe's
   console output. Printed, not chased, exactly as RUN 9 decided. It is not ours.
10. **The homepage still has no `<main>` and no skip link** while the other
    fifteen have both. Lighthouse a11y still reads 100, so no probe flags it.
    Carried forward from RUN 11 gotcha 8, still not in scope, still true.
