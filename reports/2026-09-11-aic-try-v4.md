# AIC /try v4 — PUSH TO BOOK

READ ONLY — the record of a run, not a source of truth. n8n, Retell and the repo are.

**Live:** https://aichauffeur.ai/try/ · commit `5d1fce9` · 2026-09-11

Push one button. Talk. When the call ends the page shows the trip the agent
captured, the recording so you can hear it back, the conversation, and a link to
send a partner. No call, no form.

---

## What changed

| | |
|---|---|
| **The push is instant** | The proof-of-work puzzle used to be fetched and solved *after* the tap. It is now fetched on load and solved in a worker while the visitor reads, refreshed every 150 s. Tap → create-call went **612 ms → 98 ms** at 4× CPU / Fast 3G, and the live challenge round trip to n8n (median **357 ms**) left the tap entirely. If the tap lands mid-refresh it falls back to solving right there, exactly as v3 did. |
| **The call comes back** | New read-only `GET /webhook/try/receipt?call_id=…` on WF-TRY-WEBCALL. The page polls it for 45 s after the call and renders a trip sheet, a **Hear it back** player on Retell's own recording URL, and the conversation. |
| **The page is alive** | A button that breathes until you reach for it, focus mode during a call, synthesised press / connected / ended sounds with a remembered mute, Android vibration and the iOS switch haptic, and three read-only prompt chips. |
| **Second push is clean** | Pushing again clears the previous card, player and thread, and cancels any receipt poll still in flight. |

## The gates the budget did not move

`IP_ATTEMPTS` is still **3 per IP per hour**, the daily cap is still **40**, the
**10-of-20 slot reserve** is untouched, and the 8-minute cap and 60-second
silence hang-up ride on the call exactly as before.

One number moved: **`IP_CHALLENGES` 20 → 90**. A challenge is not an attempt.
Pre-solving means one open tab asks for ~24 nonces an hour before anyone has
called anything; a nonce costs this workflow one cheap execution and costs Retell
nothing. It was already counted separately from attempts — this run did not
create that separation, it raised the headroom on it.

## The receipt, and what never leaves n8n

Origin gate → shape check → budget (15 polls per `call_id`, 60/hour per IP) →
`GET /v2/get-call` → 404 unless the call is tagged `aichauffeur.ai/try` **and**
started within two hours. Every refusal except the last happens **before** the
Retell node runs, confirmed by reading the n8n executions rather than assuming.

Returned: `status`, `pickup`, `dropoff`, `date`, `time`, `passengers`, `vehicle`,
`quote`, `ticket`, `mobile_captured`, `recording_url`, `transcript`.
Never returned: the caller's name, mobile or email. `caller_mobile` is read as a
yes/no and the digits are dropped.

## Three things this run measured rather than assumed

**1 · These calls run on Retell's GATEWAY transport, which delivers no transcript
events to the browser.** `retell-client-js-sdk@3.0.1` does emit an `update` event
carrying the running transcript — that was verified in the SDK's own source and
type definitions before a line was written. It never fired. A real call logged
**5 turns server-side and 0 on the page**. The gateway transport opens a data
channel named `control`; nothing arrived on it. So the thread cannot be drawn
live, and it fills from the receipt when the call ends instead — redacted in
three passes: the exact name / mobile / email the analyser extracted, then any
email by pattern, then any run of digits long enough to be a phone number. The
live listener stays wired for the day a call is allocated the livekit transport.

**2 · Focus mode dims to .62, not the .35 the brief asked for.** Ancestor opacity
multiplies into rendered contrast. On this ground `--ink-soft` at .35 measures
**2.17:1**. The chips are inside the dimmed group, and reading them mid-call is
their entire job — a dim that makes the one thing you are meant to read the least
legible thing on the page defeats itself. At .62, `--ink-soft` holds **4.51:1**
and `--ink` holds 6.35:1, both over the AA floor, and the panel still separates
because it keeps its own surface, its hairline and 100%.

**3 · The prompts sit below the action on a phone.** With them in the reading
column the button rendered at **911px** — off the 390×844 first screen, the one
number this page cannot get wrong. It is at **624px** now. They lose nothing:
they are what you read *while* the call runs, not before you push. At ≥1024 the
second column exists and they go back beside the headline.

## Four defects the gates caught, each wearing someone else's costume

- **A button that breathes forever has no stable bounding box**, so Playwright's
  actionability wait can never finish and `page.click()` times out. The control
  now settles on hover and focus — better for a finger too — and the gates drive
  the real pointer.
- **`getComputedStyle` one tick after a class swap returns the value
  mid-transition**, so a working 300 ms fade read as *no fade at all*.
- **`elementFromPoint` works in viewport coordinates.** An earlier chip tap had
  scrolled the page, so a correct hit test reported `nothing`.
- **`scrollIntoView({behavior:'auto'})` INHERITS `html{scroll-behavior:smooth}`**
  from `aic.css`. The rect was read while the page was still moving, the click
  landed on the Privacy link and navigated away — and it reported as *"the second
  push did not clear the card"*. A missed click wearing the costume of a broken
  feature. Proved with a negative control: `auto` fails and navigates, `instant`
  passes, same page, same code.

## Gotchas

- **The transcript is not live, and cannot be on this transport.** It appears
  when the call ends. If Retell ever moves these calls to the livekit transport
  it will start filling live with no code change.
- **The YOU level bar was not built.** `RetellWebClient.transport` is `private`
  and `analyzerComponent` is the *agent's* analyser; the only route to the
  caller's level is a second `getUserMedia`, which fights the SDK on iOS. One bar
  ships, labelled AGENT. A second bar that was not reading a level would have
  been a decoration pretending to be an instrument.
- **`mobile_captured: true` and the "texted to the number you gave" line are unit-tested, not
  proven end to end** — the test call speaks no phone number on purpose. Shane's
  iPhone pass is what proves it.
- **The iOS haptic is not claimed to work.** It is a feature-detected
  `<input type="checkbox" switch>` toggled inside the gesture, `aria-hidden`,
  `tabindex="-1"`, `pointer-events:none`. Where it is unsupported it does
  nothing, harmlessly.
- **`PUSH TO BOOK` is ALL-CAPS, which `chauffeur/DESIGN-SYSTEM.md` § 3 forbids on
  a primary control** ("Space Grotesk 600, sentence case. No ALL-CAPS"). The words
  were locked by the brief, and a direct instruction outranks the design system,
  so it ships as written — flagged here rather than resolved silently. `End call`
  is sentence case.
- **The recording is served as `application/octet-stream`** from CloudFront. It
  plays in Chromium; Safari is stricter about sniffing. If the player is silent on
  the iPhone pass, that is the reason, and the fix is an `<audio type>` hint or a
  proxy — not the URL.
- **One number moved in the budget**: `IP_CHALLENGES` 20 → 90. Attempts, the daily
  cap and the slot reserve did not.
- **The `Ticket` row renders only when a ticket exists.** Nothing writes one into
  call metadata today, so it is currently never shown; every other row shows
  `—` when the caller did not say it.
- **`Passengers` is excluded from the "did we capture anything" test.** The
  analyser returns `1` by default, so a card keyed on it would open on every call
  and say nothing but "Passengers 1".
